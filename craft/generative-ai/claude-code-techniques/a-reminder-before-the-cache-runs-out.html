Tip: Get a Mac Reminder Before Your 1-Hour Cache Runs Out

Questions this post answers

  • How do I know when my Claude Code prompt cache is about to expire?
  • Can my Mac remind me to go back to a Claude Code session before its cache runs out?
  • How do I show the prompt cache expiry time in the Claude Code status line?

What I observed​

Do you keep a lot of Claude Code sessions open at once? Then this one is for you.

After I moved my main conversations to the 1-hour prompt cache, I kept losing it anyway. I'd step into a meeting, come back 70 minutes later, and the first thing I typed would pay to write the whole conversation into the cache again. On a big session that one request costs more than the rest of the afternoon.

The hour was long enough. I just didn't know which of my 12 to 16 sessions was about to run out.

Explained simply​

  • Claude Code keeps your conversation in a prompt cache so it doesn't pay full price to send it again on every turn.
  • With the 1-hour setting, that cache lasts an hour after your last request. Each new request starts the hour again.
  • Miss the hour, and the next request writes the whole prompt again at twice the normal input price. Come back in time and it's read back at a small fraction of it.
  • So the cheapest thing you can do before a long break is send the session anything a few minutes before the hour is up. Even "ok, carry on" keeps it.

The helper on this page only tells you when. It never types for you.

What I did about it​

I asked Claude to build a reminder that watches my sessions and taps me on the shoulder before the hour runs out, with a way to jump straight to the right iTerm tab. Then I asked for the same clock in the status line, so I could see it without waiting for a pop-up.

What it looks like​

  1. The banner. It lands in Notification Center, so it's still there if you were away when it showed.
  2. The box. Same message, plus where the session lives. Go there brings up that iTerm tab. Dismiss closes it. It goes away by itself after two minutes.
  3. The status line. Every session shows when its cache runs out, as a clock time.

How it works​

  • A hook runs when a turn ends, when you send a prompt and when a session closes. It writes one small note per session: when the turn ended, where the log is, the iTerm tab's id and the folder's name. It prints nothing and always exits cleanly, so it can never hold up Claude.
  • A launch agent runs a check every minute. For each session that has been quiet for about 54 minutes, it reads the last request in the session's log: how big the prompt was, and whether it was cached for 5 minutes or an hour. That comes from what the session really did, so a session on the 5-minute cache is left alone.
  • It reminds once per pause, and only when it's worth it: a 1-hour cache, a prompt over 100,000 tokens, and not between 10 pm and 8 am.
  • The banner and box come from AppleScript. "Go there" asks iTerm2 to select the tab by the id the hook noted.
  • The status line reads the same log and prints the clock time the cache runs out.

Set it up​

You need a Mac, iTerm2, and Node 20 or newer. The helper is two files, the script and the dialog it shows, and both are public as a gist. Install it by downloading the gist or through Homebrew. Both do the same thing; Homebrew also gets you updates with brew upgrade.

  • Download the gist
  • Homebrew

  1. Get the two files. Put them in the same folder:

    mkdir -p ~/cache-nudge && cd ~/cache-nudge
    curl -fsSLO https://gist.githubusercontent.com/omars-lab/e837c737bf28718412422783f1f30812/raw/cache-nudge.mjs
    curl -fsSLO https://gist.githubusercontent.com/omars-lab/e837c737bf28718412422783f1f30812/raw/cache-nudge.applescript

  2. Install it. This copies both files into ~/.claude/hooks/, backs up your ~/.claude/settings.json, adds three hook entries to it, and loads the launch agent:

    node cache-nudge.mjs install

    Sessions that are already open pick up the hook only after you restart them.

  3. Try it once from an iTerm tab. This lines up a reminder for the tab you're in, so you can see the box and press Go there:

    node ~/.claude/hooks/claude-cache-nudge.mjs try --transcript <this session's log>

    The first time, macOS asks whether it may control iTerm. Click Allow.

  4. Check it's on whenever a reminder doesn't show:

    node ~/.claude/hooks/claude-cache-nudge.mjs status

  1. Install it. Homebrew only runs formulas from taps you trust, so add the tap, then trust this one formula in it:

    brew tap omars-lab/tap
    brew trust --formula omars-lab/tap/claude-cache-nudge
    brew install omars-lab/tap/claude-cache-nudge

  2. Add the hooks, then start the check. Homebrew never edits ~/.claude, so this step is yours. It backs up your ~/.claude/settings.json and adds three hook entries that call the claude-cache-nudge command. Then brew services runs the check every minute:

    claude-cache-nudge install
    brew services start claude-cache-nudge

    Sessions that are already open pick up the hook only after you restart them.

  3. Try it once from an iTerm tab. This lines up a reminder for the tab you're in, so you can see the box and press Go there:

    claude-cache-nudge try --transcript <this session's log>

    The first time, macOS asks whether it may control iTerm. Click Allow.

  4. Check it's on whenever a reminder doesn't show:

    claude-cache-nudge status

With Homebrew, use claude-cache-nudge wherever the rest of this page says node ~/.claude/hooks/claude-cache-nudge.mjs.

Read the script before you run it. The download and Homebrew both install this same file:

Add the clock to your status line​

The status line shows a clock time, not a countdown. Claude Code only redraws the status line when something happens in the session, so a countdown would sit frozen while you're away. The clock time stays true.

  • You already have a status line script
  • You don't have one yet

Add these two lines after your script reads its input into $input:

cache_seg=$(echo "$input" | node ~/.claude/hooks/claude-cache-nudge.mjs statusline 2>/dev/null)
[[ -n "$cache_seg" ]] && output+=" | ⏳${cache_seg}"

Point the status line straight at the script in ~/.claude/settings.json:

{
  "statusLine": {
    "type": "command",
    "command": "node ~/.claude/hooks/claude-cache-nudge.mjs statusline"
  }
}

It prints cache till 3:42 PM (1h), or cache expired (1h) once the hour has passed.

Change the defaults​

Put any of these in ~/.claude/cache-nudge/config.json:

SettingDefaultWhat it does
minTokens100000Skip prompts smaller than this; they cost little to write again
leadMinutes5How many minutes before the end to remind you
quietStart / quietEnd22 / 8No reminders between these hours
forgetHours6Drop a session's note after this long

To turn it all off: node ~/.claude/hooks/claude-cache-nudge.mjs uninstall. It removes exactly what install added and keeps the log and the settings backups. With Homebrew, run claude-cache-nudge uninstall, then brew services stop claude-cache-nudge and brew uninstall claude-cache-nudge.

Words of caution​

  • It only reminds. It never types into a tab or sends a prompt to keep a cache warm. You decide whether the session is worth keeping.
  • The banner shows up as "Script Editor" in System Settings → Notifications, because that's what posts it. If you see the box but no banner, turn notifications on there. Clicking the banner opens Script Editor, so the jump to iTerm lives in the box.
  • Other tools can rewrite your settings file and drop the hook entries. The reminders then stop with no error. status says hooks: MISSING when that happens; run install again.
  • It's iTerm2 only for the jump. In another terminal you still get the banner and the box, with just an OK button.
  • Your notes and log stay on your Mac, in ~/.claude/cache-nudge/. They hold folder names and session ids, so keep them out of anything you share.

Why it works​

  • The cost of a miss is lopsided. Keeping the cache costs one small request. Losing it costs a full rewrite at twice the input price.
  • The log already knows. Every request's time, size and cache length is in the session's log, so nothing has to guess.
  • A reminder beats a habit. With a dozen sessions open, you can't keep a dozen clocks in your head. A tap on the shoulder five minutes out is enough.
